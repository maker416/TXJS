# 绿色玩家卡片 · 静态演示

这个独立美术包演示等待战斗室的左侧头像格，以及名字、位置、队伍、延迟下方的信息行。外观采用深色底与绿色边框，房主使用金色徽章，AI 示例使用紫色、蓝色和绿色徽章。真人优先显示可用的账号头像；本包未提供默认头像图片，没有可用账号头像时使用客户端内置真人图标，AI 使用内置机器人图标。

需要包含 `[room.player.card]` 功能的客户端。旧包、旧版房间布局字段的兼容规则见[战斗室美术包开发](../../../docs/战斗室美术包开发.md)。本包只扩展玩家槽位内部，房间面板仍按客户端的 PC、Android 和窗口尺寸规则排列。

## 内容来源

`theme.toml` 中的胜负数、专家称号和 AI 难度文案全部是固定演示内容，不代表实际账号战绩或 AI 配置。名字、位置、队伍、延迟、准备状态、同步进度和名片继续读取真实业务状态。账号头像是独立的动态数据，不受这些写死文案影响。

本机玩家可直接取 `AccountSession` 中已登录账号的头像。远端玩家须经已有房间身份服务确认，服务需支持 `room_id_membership_verified`；客户端不凭游戏昵称猜账号。服务不支持核验、身份未知、未设置头像或头像加载失败时使用主题默认头像，再回落内置图标。因此不能保证房间里所有登录玩家都显示账号头像。

- 通用玩家显示“联机玩家”和“战绩：128胜 / 23负”。
- 房主显示金色“房主”徽章；AI 默认显示“进攻专家”。角色选择来自客户端真实状态。
- 出生位置 2、3、4 分别显示“防守大师”“进攻专家”“经济发展”。这是位置覆盖，真人进入相同位置也会看到同样的静态文案。
- 观战玩家显示“观战席”和“静态信息展示”。

指定出生位置优先于本机、房主、AI 和观战内容，命中后整份替换通用内容；此示例没有本机专用覆盖，以便本机房主仍显示房主内容。需要动态数据时应在客户端增加正式数据来源，目前不支持网络接口、变量占位或脚本。

## 导入与修改

将本目录的 `theme.toml` 放在 ZIP 根目录，后缀改为 `.rwtheme`。从“主界面 → 资源中心 → 扩展（美术包管理）”导入并启用。交付包输出位置为仓库根目录下 `build/artifacts/room-player-cards/room-player-cards.rwtheme`。

编辑 `[[room.player.card.<内容>.rows]]` 的 `cells` 可以增加文字格；一个 `rows` 表代表一行，最多三行，每行最多四格。使用 `card.content` 配置通用内容，`card.local`、`host`、`ai`、`spectator` 配置真实角色的覆盖，`card.slots."1"` 等配置出生位置。默认头像可通过相应内容的 `avatarImage` 指定包内相对路径；这些字段仅在没有可用账号头像时生效，不能覆盖真实账号头像，缺失或损坏时回落内置图标。AI 使用主题默认头像或内置机器人图标。

将 `[room.player.card.avatar]` 的 `enabled` 改为 false 可隐藏头像格并保留信息行；将 `[room.player.card]` 的 `enabled` 改为 false 可恢复原玩家行，只保留配色与边框。

修改已安装的包时，先退出房间，停用并等待刷新完成，删除旧包后再导入。替换下载目录里的 `.rwtheme` 文件不会更新已安装副本。

## 验证

检查长昵称、满员滚动、狭窄窗口、准备/同步进度、名片点击，以及切换或停用主题后的恢复。还应验证本机账号头像、远端已核验头像和各类默认头像回落。绿色卡片中的额外文案是静态展示，账号头像按实际身份动态加载；本包不提供用户参考图中的房间整体重排。桌面 Compose 测试截图不能代替 Android 真机与联网测试。
