# 客户端积分支付

更新时间：2026-11-17。

## 用户入口

账号中心「积分」中的「积分支付」接受开放平台支付 ID；「安全」中的「支付密码管理」用于首次设置或重置六位数字支付密码。

支付 ID 是开放平台创建的 UUID，不是开发者自己的商户订单号。客户端从固定官方平台读取订单，展示收款应用、商品、积分数量、当前已知余额及状态；UAS 和开放平台均验证登录账号是原单指定的付款人。每次付款需要用户核对并输入独立支付密码，设置密码不会自动付款。

首次设置、修改或忘记密码均验证当前 UAS 绑定邮箱。没有邮箱时跳转现有邮箱绑定入口，重新登录相同账号后恢复原支付单；绑定前只在内存保留订单 ID 与付款账号，不保存密码或验证码。改用其他账号不会恢复前一账号订单。

## 服务契约

UAS 使用当前客户端 AppKey 和用户 JWT：

| 接口 | 内容 |
| --- | --- |
| `GET /api/v1/users/payment-password` | `has_password,email_masked,email_bound,locked_until` |
| `POST /api/v1/users/payment-password/send-code` | `{purpose:"setup"或"reset"}`；邮箱由 UAS 确定 |
| `POST /api/v1/users/payment-password/setup` | `{code,password}` |
| `POST /api/v1/users/payment-password/reset` | `{code,password}` |
| `POST /api/v1/payment-authorizations` | `{payment_id,payment_password}` → `{ticket,expires_at}` |

官方开放平台也使用原客户端 AppKey 和用户 JWT 核验身份；其响应沿用 `code/message/data/request_id` 外层：

| 接口 | 内容 |
| --- | --- |
| `GET /api/v1/client/payments/{id}` | 读取订单和最终结果 |
| `POST /api/v1/client/payments/{id}/confirm` | `{ticket}`，允许 `202` 处理中 |

客户端订单字段为 `id,app_id,app_name,subject,payer_account_id,point_type_id,points,status,expires_at,last_error`，时间为 Unix 秒。状态为 `preparing/pending/processing/closing/succeeded/closed/refunded`。仅 `pending` 可以新确认；处理中和关闭核实中轮询同一订单，超时不会显示为确定失败，也不会自行创建或支付替代订单。用户关闭界面只取消本地请求，不撤销已受理付款。

绑定邮箱变更增加原邮箱验证：`POST /api/v1/users/change-email/send-old-code` 发当前邮箱验证码，现有 `change-email` 请求携带 `old_email_code` 或 `payment_password` 二选一。首次绑定无旧邮箱时仅验证新邮箱。

## 网游拉起

游戏服务端可通过既有房间聊天机制向目标玩家发送以下完整消息：

```text
[RWJSPAY1] 11111111-2222-3333-4444-555555555555
```

客户端只识别严格的小写 UUID；只有房内唯一昵称的真实房主或引擎服务器消息可拉起，每十五秒至多一次，当前已经打开支付界面时不替换。其他玩家发送的消息按普通聊天展示。消息只负责请求预览，不能包含金额、支付密码、JWT、票据或 API Secret。交易权威内容和付款归属仍以官方接口为准。

Android 与桌面端共用 `UI.onReceiveChatMessage`、`PaymentController` 和原生确认弹窗。游戏画面隐藏启动器时，订单入口在启动器账号页可见；付款不会阻塞游戏线程。

## 安全与部署

敏感支付请求只接受 HTTPS；HTTP 仅允许字面回环开发地址，回环直连、不经过代理。UAS 和官方平台均禁止重定向，响应正文有大小上限，客户端从不携带 AppSecret。现有普通账号 HTTP 兼容配置保持原用途，支付密码页面会明确提示必须配置安全 UAS 地址；部署者须先启用 UAS HTTPS，再开放支付。

PIN 只发 UAS，一次性授权票据只发官方平台。PIN、验证码和票据不写配置、不打日志、不放入游戏消息；弹窗关闭、登出或切号立即取消请求并清理输入。旧请求即使迟到也不能回写新账号界面。UAS 负责全局密码失败锁定、验证码频率及票据过期控制。

## 验证

```powershell
./gradlew.bat :rwpp-core-api:test --tests PaymentClientTest
./gradlew.bat :rwpp-core:desktopTest --tests PaymentUiTest
./gradlew.bat :rwpp-core:compileKotlinDesktop :rwpp-android:assembleDebug :rwpp-desktop:compileKotlin
```

网络测试覆盖两端凭据隔离、原单账号匹配、HTTP/重定向拒绝、响应上限、错误脱敏、关闭取消及消息格式；原生界面测试覆盖设置密码后重新确认、登出取消迟到订单、同一帧关闭重开销毁旧 PIN。真实邮箱投递、生产 HTTPS、实际积分扣款与开发者钱包到账仍需同已部署服务联调。

### Android 实机隔离宿主

`./gradlew.bat :rwpp-android:assembleDebug -PpaymentUiTestPackage=true` 生成独立的 `io.github.rwjs.paymenttest` 调试包，避免覆盖设备上签名不同的正式客户端。仅该测试包可以运行调试专用 `PaymentUiHostActivity`；宿主在独立进程内使用内存配置，不读取或写入玩家账号配置。生产 Release 不包含该入口。

宿主通过 ADB 参数接收 `uas_url`、`platform_url`、公开 `app_key` 和 `payment_id`，服务地址必须是字面回环。正常模式由原生登录界面向合成 UAS 获取登录会话，不接受通过 ADB 注入 JWT。添加 `insecure=true` 使用内置非 JWT 预览身份验证公网 HTTP 被本地拒绝；`landscape=true` 用于横屏布局验证。仅在专用测试库和合成账号上使用，通过 `adb reverse` 映射两个本机服务端口。

该独立测试变体在手机桌面显示「RWJS支付联调」。手动打开时默认连接本机映射的 18080/18081 端口，使用公开的合成客户端标识；用户正常登录合成账号后，宿主从仅测试用的 `/test/new-order` 创建本人订单，再进入真实支付确认。宿主不预填登录密码、支付密码或 JWT。普通 Debug 保留原启动器入口且禁用该测试 Launcher，Release 不包含测试 Activity。
