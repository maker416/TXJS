# 浏览器独立组件版本验证报告

日期：2026-11-01。本轮在现有工作区继续修改，保留客户端版本 `1.20.55`，未发布或上传 Gitee Release。最终执行的真机测试只使用 Redmi K30 Pro（序列号 `2993cd77`、Android 10、arm64）。

## 当前行为

- Gecko 与 JCEF 各自使用独立组件版本，正式组件初始版本均为 `1.0.0`，在 `packaging/browser-kernels.properties` 维护。完整上游版本不变。
- 文件名携带组件版本，例如 `RWJS-Browser-gecko-android-arm64-v8a-v1.0.0.kernel.001`；客户端按数字比较版本，要求文件名、清单和分卷前缀一致。
- 进入论坛或赛事页时只检查最新 Gitee Release。客户端只选择完整引擎版本、加载格式、平台和架构兼容且不低于客户端基线的组件。存在兼容更新时显示当前版本、目标版本及下载量。
- 网络检查失败时继续使用已验证的兼容本地组件；最新发行版版本较低时不降级；同版本换内容时不覆盖本地组件。
- 未加载内核的进程可以直接启用下载的新组件；已加载旧内核的进程只安装新包并提示重启，也可继续使用当前版本。
- 按用户明确选择，信任我们最新 Release 的远端清单，不新增签名密钥。分卷、完整 ZIP 和解压文件仍验证 SHA-256；该方式不能防止清单和附件被同时替换。此前固定历史 tag、远端清单必须命中主包哈希的方式已被本方案替代。

本地发布组件为 `1.0.0`。为证明加载器没有固定到主包基线目录，测试 fixture 在独立目录中把相同官方原生内容重新标记为测试版本 `1.0.1`，宿主仍携带基线 `1.0.0`。K30 上不存在 `-k1.0.0` 安装目录，实际通过活动指针加载 `-k1.0.1`。该测试版本不在正式发布附件目录中。

两轮完整测试及路径测试期间，fixture 的 `.kernel.001` 请求总计只有一次，说明进程重启后没有重下组件分卷。仪器测试准备阶段仍会请求本地测试清单；完全断网时的回退由共享界面测试覆盖，不能把这几轮仪器测试描述成零 HTTP 请求。

测试使用独立包 `io.github.rwjs.browserkerneltest`，没有覆盖正式客户端。网页、票据、Cookie 和上传文件均来自本地测试夹具，没有操作真实账号或线上论坛。
