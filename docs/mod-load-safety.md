# 模组加载、内存保护与恢复

模组文件大小不能换算为加载堆占用。单位表达式、继承、注册表、解析临时对象和重载期间仍可达的旧对象都会影响峰值；Java 堆和贴图、音频的 native 内存也需分开观察。

## 数据传输

同步主路径使用文件：下载以 64 KiB 缓冲写入私有临时文件，检查长度与 SHA-256 后交给缓存；房主先流式生成不可变磁盘快照，再上传快照，清单与上传字节保持一致。目录模组沿用确定性 ZIP 顺序、时间戳与压缩级别，不改变校验身份。成功、失败和取消都清理本轮临时文件，下个进程首次传输时清理中断留下的专用临时文件。

Range 续传校验起止位置、总长度、响应长度；服务器忽略 Range 返回 200 时重新写入。损坏校验、错误区间、超长响应和磁盘写入错误不会发布缓存。旧 ByteArray API 仅为兼容保留，应用同步流程不再使用。

PC 缓存 v2 使用 1 MiB AES-GCM 分块，认证文件头、块序号和块长度，结束时验证总 SHA-256。解密输出只进入临时文件，全部成功后换名发布；认证失败不能覆盖旧活动副本。启动按有界文件头排序，但只有完整认证后的条目可进入索引；本轮验证同时输出最新活动副本，保留启动优化的一次解密流程。

v2 存放在 `.rwpp/network-mod-cache-v2/`。旧 v1 加密缓存留在原位置，升级后作为缓存未命中重新下载，不尝试以整个文件解密迁移。原始用户模组不受此缓存版本变化影响。

## 资源加载保护

### 深层 select 表达式

`SelectChainParser` 优化至少 32 层、语法严格匹配的 `select(condition, yes, select(...))` 链。一次扫描记录括号位置，使用原字符串区间解析各条件和分支，逆序组装原版 `LogicString.Select` 节点，避免每层递归同时保留越来越长的子串。解析顺序、返回类型检查和 `validateAndOptimize` 保持原版调用；普通表达式及无法证明兼容的语法回退原版。两端 `SelectLoadInject` 只挂在 `setArgumentsRaw`，不引入新的表达式类型或网络格式。

实际旧版“安绒宁静”包含 1,539 层 select。Android 压力快照中约 350 MiB 是字符数组；优化后该模组单独启动和重载通过。原版客户端也能加载此模组，因此不能把所有峰值失败归因于文件太大。完整实测和边界见[验证报告](mod-memory-recovery-validation.md)。

`ModLoadSafety` 包住启动、普通重载、保连接重载和辅助重载。在单位与表达式解析入口检查实际 Java 堆余量，保留 `maxHeap / 10`，下限 32 MiB、上限 128 MiB。达到阈值先执行 GC 再判断；每次低余量都重新判断，不能把整轮只允许一次 GC 当作预算，否则长期解析产生的可回收对象会造成误拦。

仍无足够余量时用预分配、无堆栈的内部信号中止解析，外层转成 `ModLoadFailure(memoryExhausted=true)`。原引擎包装的 OOM 也检查 cause 链。普通资源加载失败使用不同失败类型。失败不允许继续刷新地图、校验损坏注册表或上报同步成功，等待解析退出后关闭连接并清理 Presence，不再进行第二次原版回落加载。

`GameStartSafety` 是进程级闸门，退房不清除此状态。失败界面只提供退出；退出路径不遍历或保存损坏的引擎对象。普通的模组格式错误如果由引擎正常记录并完成注册表，仍沿用原有模组错误提示。

Android 特别约束：队列任务在 `a(float,int)` 原始帧开始前消费，并在任务结束后重新检查失败状态。不能在帧中途的 `b(float)` 消费重载后只等待下一帧再检查；当前帧也可能访问已清理的单位表。失败时两处帧入口都跳过原方法。引擎入口的 UI/游戏线程契约仍保持；PC 普通重载仍在主 GL 线程，保连接解析仍使用共享 GL 工作线程。

`[MODMEM]` 记录阶段、结果、开始占用、检查点观测峰值、结束占用和 JVM 堆上限。这里的 peak 是检查点观测值，不是连续采样的绝对峰值，也不包含 native 堆。

## 启动恢复

加载前原子写入小型 `resource-load.properties`，记录 attempt/session、阶段、最后处理的模组与失败类型。正常加载成功才清除对应 attempt；旧任务不能清除新任务的记录。进程被系统杀死或用户强行关闭时可能留下未完成记录，因此恢复页不把所有中断都称为 OOM。

Android 使用原生控件、PC 使用 Swing，在解析引擎单位前读取恢复记录。恢复页只枚举模组容器，不解压或加载缩略图。用户可选择本轮组合、重试原配置或退出；本轮默认不启用自定义模组。`.zip` 外层集合不会被误列为原版引擎可扫描的 `.rwmod`。

恢复选择仅在本次进程中覆盖扫描结果，并拦截引擎保存模组开关。临时恢复成功后仍保留恢复标记，避免下次又自动加载未修改的旧组合。只有模组页明确发起应用/重载，才提交新的选择。Android 初始化由进程持有，Activity 重建等待同一结果，不复用未完成的半初始化单例，也不因资源失败删除已生成 DEX。

检查点无法保证任意一次巨大分配、驱动崩溃或系统杀进程都能被进程内恢复。预写日志用于下一次启动脱离重复加载；是否能运行某组模组仍取决于设备实际容量。

## 验证

```powershell
.\gradlew.bat :rwpp-core-api:test :rwpp-core-api:resourceLoadSafetyTest :rwpp-core-api:lowMemoryModTransferTest
.\gradlew.bat :rwpp-core:desktopTest :rwpp-desktop:test :rwpp-android:testDebugUnitTest
.\gradlew.bat :rwpp-android:assembleRelease
```

`resourceLoadSafetyTest` 每个测试类独立 JVM、96 MiB 堆，验证保护状态不可在同一进程内解除、包装 OOM、普通失败、恢复选择与实际分配压力。`lowMemoryModTransferTest` 在 96 MiB 堆中流式下载、上传、加解密 60 MiB 文件。另覆盖 Range、中途取消、认证破坏、交换块、发布失败保留旧文件、PC 连接回调先于句柄返回、重复打开加载框后取消、Android 文档 URI 真实文件名识别和原子导入。

Android `ResourceFailureFrameTest` 直接调用真实帧注入函数：队列内设置失败后，同一帧必须返回中断，不能接触引擎或继续单位更新。PC 注入测试将生成的预算/恢复配置应用到真实游戏 JAR 并验证字节码。

实测记录见[本次修复的验证报告](mod-memory-recovery-validation.md)；有限次数连续重载不能排除所有模组组合或对局状态下的内存泄漏。
