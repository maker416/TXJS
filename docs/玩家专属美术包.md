# 玩家专属美术包与房间身份核验

本功能由 TXJS、开放平台以及可选的 TServer UAS 身份插件共同提供。外观资源和文案预先写在美术包内，平台只分配变体标识。只有当前游戏连接经过核验，且观察者启用包含该内容的美术包时，才显示玩家专属外观。旧服务器、未登录、隐藏身份、服务故障或身份冲突时使用美术包原有默认外观。

## 作者使用流程

1. 在开放平台创建应用，进入“美术包”登记一个包，取得永久平台包 ID。
2. 把 ID 填进 `theme.toml` 的 `personalization.platformPackId`，定义需要的变体。修改素材或清单后要重新登记发布版本。
3. 将 `.rwtheme` 导入客户端。在该包卡片点击“复制平台发布目录”，将 JSON 粘贴到开放平台对应包的发布页。目录包含原始清单及引用资源的 SHA-256；不包含账号和凭据。
4. 在平台选择玩家的 **UAS 全局 account_id**、外观插槽和变体，设置可选到期时间。应用成员 `user.id`、游戏昵称和出生位置不能作为账号 ID。
5. 玩家登录 TXJS，加入已登记端点、装有 UAS 身份插件的 TServer。其他启用同包的玩家会看到分配的外观。发布目录不匹配、变体不存在或尚未分配时保留默认。

完整最小示例在 [examples/themes/personalized-player](../examples/themes/personalized-player/README.md)。

## 配置格式

```toml
[personalization]
schemaVersion = 1
platformPackId = "00000000-0000-4000-8000-000000000001" # 替换为平台签发 ID

[personalization.slots."room.player.background".variants.gold]
image = "players/gold.png"

[personalization.slots."room.player.frame".variants.gold]
borderColor = "#FFD166"
borderWidth = 3
displayName = "棱镜之冠"
avatarFrameImage = "players/prism.png"

[[personalization.slots."room.player.badges".variants.supporter.content.rows]]
cells = [{ text = "美术包支持者", contentColor = "#FFD166" }]

[[personalization.slots."room.player.info".variants.author.content.rows]]
cells = [{ text = "此美术包的作者", contentColor = "#B8D8FF" }]
```

支持四种插槽：`room.player.background` 使用包内 `image`；`room.player.frame` 使用 `borderColor` 和 `borderWidth`（0–6dp）；`room.player.badges` 与 `room.player.info` 复用现有卡片 `content.rows`。徽章行放在信息行之前，个性化 info 替换普通静态信息行；合计最多 12 行，每行最多 12 格，沿用原有尺寸、折行和路径限制。它们可独立于普通 `card.enabled` 显示，不覆盖真实账号头像。

每个插槽最多 64 个变体，变体 ID 为小写字母开头的 `[a-z][a-z0-9_-]{0,63}`。未知插槽忽略；未知 schema 关闭个性化而保留默认美术。危险路径拒绝导入；引用素材缺失、资源超限或摘要失败时关闭个性化。客户端定义可绘制字段，平台不能注入 URL、路径、脚本或任意文案。

### 战役室名片与头像框

玩家打开自己的名片后可以点「试穿装扮」，分别预览卡面和头像框。试穿只在当前弹窗生效，结束后显示平台已分配的组合。打开其他玩家的名片时，卡面和头像框使用房间中该玩家已核验的分配。

- 卡面沿用 `room.player.background.image`。建议使用 3:1 横向构图，主体靠右，并让左侧留出头像和名字的位置。
- 头像框可在 `room.player.frame` 变体中设置 `avatarFrameImage`。使用正方形透明 PNG，将图案沿边缘绘制，中央约 72% 直径留给真实头像。该文件参与发布目录摘要。已有纯描边变体继续按颜色和宽度显示。
- 两个插槽都可设置 `displayName` 作为试穿时的商品名称，最多 48 个字符，省略时显示变体 ID。使用新贴图的美术包应从新版客户端导出发布目录并登记新版本。

## 身份与兼容

客户端只对开放平台管理员登记的实际游戏 Socket IP/端口启用核验。插件在宿主确认真实注册完成后，向该连接发送“已连接，支持玩家专属外观。”欢迎私信；客户端必须在当前 Socket 的原始包141中确认 `sender=RWJS-ID`、`sourceConnection=0` 及精确文本后，才发起 `/txjsid hello <nonce>`。玩家即使改成相同昵称，其原版转发消息的 source 也非零，不能冒充这个通知。首包115或两次 UI 采样都不是注册完成证据，不能据此提前发送认证命令。

插件从宿主收到真实 `MessageTarget`，通过 HTTPS 创建与该连接及房间实例绑定的挑战，私信返回 `[RWJSID1]` 控制行。客户端继续检查同一个 Socket、原始服务器 source、本轮随机 nonce 和登记服务器，再通过官方 HTTPS 桥接，以自身允许的 UAS AppKey/Bearer 核验账号并取得短期一次性票据。随后仅将该票据句柄通过 `/txjsid prove` 发回原游戏连接。

插件使用该命令的真实发送连接消费票据；平台将核验结果绑定到 `server_id + room_instance_id + connection_id`。插件每三秒发布当前完整槽位快照，平台只从已消费的连接证据派生账号，拒绝成员表自报 `account_id`。玩家换位更新当前槽位，断连、登出和 clear 撤销绑定；旧异步结果须检查连接和代次。

观察者用自己的短期 observer token 读取同房名册，无需将账号凭据发送给房主。客户端每五秒读取名册，批量查询当前包内这些账号的分配；分配最多缓存 30 秒，并受服务端 60 秒有效期限制。名册 15 秒失效，账号绑定和观察会话最长 120 秒，客户端约 90 秒刷新挑战。不可见时暂停展示轮询，恢复后重查；登出/切号先作废本地结果。

昵称仅用于与当前引擎槽位快照进行一致性检查，不用于查账号。`connectHexId`、旧 relaymod 自报公示、IP 和玩家指纹均不提升为账号认证。名册重复槽位/账号、对象替换、过期、旧修订、换包或 HTTP 错误都回落默认。

游戏包号、Direct v2 query、原版注册与 checksum 流程保持原样。身份插件只影响外观，移除后原版及旧 TXJS 客户端仍可正常游戏。当前游戏传输仍为原版明文；本功能不宣称抵御主动中间人或恶意受信游戏服务器，若需此保证还须独立完成端点认证及加密通道。

## 管理员接入

网游开发者现在通过开放平台「网游」提交上架申请，绑定本应用的美术包发布版本，并登记区服实际 IP:port。管理员分别审核网游及区服后，开发者在区服卡片生成一次性接入配置，复制到 `plugins/rwjs-uas-identity/uas-identity.properties`。配置包含 `openPlatformUrl`、`gameAppId`、`serverId`、`serverSecret`；无需管理员手动登记动态区服或重启平台。区服密钥只能心跳及核验本节点，不能发布包或修改玩家分配。密钥重置、撤销、下架或地址变更会使旧核验凭据失效。

管理员原有 `identity_servers` 静态登记继续兼容；静态插件配置不填 `gameAppId`。平台仍须配置 `identity_app_keys`，允许 TXJS 原 UAS 应用 Key 向固定 UAS 服务核验。节点 secret 只保存在平台和插件本地配置；普通开发者应用凭据不能自行获得服务器核验权。公网服务使用 HTTPS，环回测试可使用 HTTP。目录、加入与临时切换见[网游上架与玩法大厅](网游上架与玩法大厅.md)。

TServer 在最新 API27 上加载独立 `uas-identity` 插件，并保持 `/` 命令前缀。插件源码位于同级 `TS/uas-identity` 项目，其《开发指南.md》包含 SDK 固定版本、配置路径、权限、构建与验证。UAS schema、核验交互及 HTTP 业务留在插件和开放平台，TServer 本体不识别美术包。

开放平台首次升级应使用其顺序迁移命令。数据库迁移与服务部署不由客户端执行；不要把平台配置、UAS Token 或服务器 secret 放进 `.rwtheme`。身份票据和观察令牌只保存在有界内存，服务重启后重新核验。

## 发布摘要

对 `theme.toml` 原始字节计算小写 SHA-256。对所有归一化后个性化配置实际引用的资源流式计算 SHA-256；资源路径按 **UTF-8 字节序**排序。下列 UTF-8 文本的 SHA-256 即 `catalog_hash`：

```text
RWJS-ART-CATALOG-1\n
<manifest_sha256>\n
<relative_path>\t<asset_sha256>\n
...
```

上述 `\n` 和 `\t` 表示实际换行及制表符，不是反斜杠文本。每份资源最多 32MiB，总计最多 128MiB、最多 256 个引用路径；禁止大小写冲突路径和越出包根的符号链接。清单或任意引用资源改变都会得到新摘要。平台复算摘要并保持已发布版本不可原地改写，已有旧版本可继续解析其仍存在的变体。
