# RWJS 主题美术包开发文档 v3：新版卡片主页

校准日期：2026-11-11。本文以当前仓库的 `ArtThemeSpec`、`ArtThemeController`、`LauncherMainMenu`、`LauncherThemeStyle` 和 `ResourceCenter` 为准，适用于包含新版卡片适配的客户端构建。v3 是文档修订号，不是包内必填的版本字段。

当前客户端还支持等待战斗室：独立背景、玩家槽位图片、字体、配色及按钮外观，内置外观和旧包默认显示玩家头像格；`[room.player.card] enabled = true` 仅开启静态附加信息行，头像设置独立生效，详见[等待战斗室美术包开发](战斗室美术包开发.md)。头像随稳定内容高度自适应至配置上限，全表头像列宽一致，临时同步进度不改变头像尺寸和列宽。头像格优先显示已识别账号的真实头像，美术包的 `avatarImage` 仅提供默认头像；远端账号识别依赖支持成员核验的身份服务，无法识别时回落默认。PC 和 Android 分别使用内置房间面板布局；旧布局字段仍被忽略。`[room]` 与本文的 `[menu]` 独立；旧包不填写 `[room]` 也能正常使用。

美术包是后缀为 `.rwtheme` 的 ZIP，通过资产、颜色、文案与响应式卡片布局改变启动器外观。它不提供 HTML、Compose 或脚本形式的任意主页。本文同时面向人工作者和 AI 制作者。

## 1. 能力与边界

| 设计目标 | 当前能力 |
|---|---|
| 更换背景、标题、卡片图、字体、音乐、文字与配色 | 支持；所有主题仍使用新版原生卡片 |
| 保留六卡排布，只更换样式 | 支持；不要填写布局结构字段 |
| 改为竖排、三/四列、改变排序/占列/隐藏 | 支持；小屏自动减少列数，内容可滚动 |
| 主页新增论坛、赛事或管理直达卡 | 声明对应槽位或放入对应按钮图即可 |
| 只修改资源中心内的论坛卡片 | 没有页面独立命名空间；同槽位声明或图片也会在主页增加直达卡 |
| 改每个主页按钮的文字颜色、字号、图标、内边距或删除箭头 | 没有独立字段；配色走 ColorScheme，原生内容仍存在；战斗室按钮另见专章 |
| 隐藏顶部账号、好友、固定管理入口或底部退出栏 | 不支持；管理入口必须始终可达 |
| 按钮图使用 Fit、任意轮廓命中、绝对定位或点击脚本 | 不支持；图片固定 Crop，命中区域仍是原生卡片 |
| 修改游戏单位逻辑、网络协议或模组包内图片 | 不属于主题能力 |

不要把一张假的整屏主页截图当作示例包交付。标题、按钮与文案应来自真实资产或覆盖键，原生点击和响应式排布仍需工作。

## 2. 文件格式与导入

```text
my-theme.rwtheme（ZIP 根目录）
├── theme.toml                 必需
├── background.png             可选，也可为 background.jpg
├── title.png                  可选，透明宽幅标题
├── icon.png                   可选，管理页缩略图
├── strings_zh.toml             可选，中文文案
├── strings_en.toml             可选，英文文案
├── buttons/
│   ├── singlePlayer.png
│   ├── multiplayer.png
│   └── resources.png
├── fonts/regular.ttf           路径由配置指定
├── music.ogg                  可选
└── game/units/...              可选，原版游戏美术覆盖
```

ZIP 内直接放 `theme.toml`，不能再套一层目录。不要用 RAR/7z 文件只改后缀。文本用 UTF-8，路径使用 `/`，禁止绝对路径、盘符、反斜杠与 `..`。

从「主界面 → 资源中心 → 扩展（美术包管理）」导入，然后手动启用。主页和资源中心页头也有固定管理入口。导入与启用是两个动作。同一 id 不能覆盖导入；更新时先停用、等待刷新结束、删除旧包，再导入。

## 3. 一个可直接使用的配置

```toml
[theme]
id = "my-card-theme"
name = "我的卡片主题"
author = "作者"
version = "1.0.0"
description = "使用新版主页的资源主题"

[colors]
primary = "#D9A65C"
primaryContainer = "#243A4A"
onPrimaryContainer = "#FAF3DE"
secondaryContainer = "#354A54"
onSecondaryContainer = "#FAF3DE"
background = "#172630"
surface = "#24313A"
onSurface = "#FAF3DE"
surfaceContainer = "#60717A"

[menu]
showTitleBadge = false

[menu.layout]
orientation = "grid"
columns = 2
align = "center"
widthPercent = 84
buttonHeight = 72
buttonCorner = 8
spacing = 12
showBorder = false

[menu.buttons.singlePlayer]
order = -2
span = 1

[menu.buttons.multiplayer]
order = -1
span = 1

[menu.buttons.resources]
span = 2

[menu.buttons.mods]
widthPercent = 94
```

`id` 只能包含英文字母、数字、下划线与连字符；`name` 必填。`version` 是作者版本号，不会为旧客户端开启新功能。普通未知字段可能静默忽略，导入成功不表示字段一定被读取。

## 4. 默认主页与自定义网格

解析模型默认值与新版页面默认布局是两个概念。只放资产或配色时，保留新版双主卡加工具区。仅按钮图片、单卡宽度/描边、全局高度/圆角/描边也保留这个结构。

显式设置以下任一结构字段会进入新版自定义卡片网格：`orientation`、`columns`、`align`、`offsetY`、全局 `widthPercent`、`spacing`。值即使等于模型默认值也生效。按钮的非默认 `order/span/hidden`，或显式声明论坛、赛事、扩展直达槽位，也会进入网格。未知按钮 id 的配置不会改变布局。

| `[menu.layout]` 字段 | 模型默认值 | 范围与实际行为 |
|---|---|---|
| orientation | grid | grid / vertical；vertical 为一列 |
| columns | 2 | 1–4，实际列数受屏幕宽度限制 |
| align | center | top / center / bottom，标题与卡片整体对齐 |
| offsetY | 0 | -400–400dp；正数增加上方可滚动留白，负数增加下方留白；不是绝对定位 |
| widthPercent | 65 | 30–100；主页宽度为 min(逻辑视口宽度 × 百分比, 880dp) |
| buttonHeight | 44 | 28–96dp，是高度下限；标题、说明和内边距可撑高卡片；点击高度至少48dp |
| buttonCorner | 20 | 0–32dp；未填写时保留新版主卡/工具卡圆角，显式20则确实使用20dp |
| spacing | 10 | 0–32dp，行列间距 |
| showBorder | true | 控制原生默认描边；单卡可以覆盖 |

主页卡片区水平居中；100% 在窄屏可贴近边缘，建议自行预留视觉留白。1600dp 视口下65%与80%均超过880dp，因此最终宽度相同。

主页网格按每列约160dp加间距估算容量；资源中心按约200dp估算。同一份配置在两页的列数不保证相同。窄屏先减列，再将 span 限制到实际列数。网格先按 order 稳定排序，再逐行放置；放不下时换行，不回填之前的空格。

## 5. 槽位、文案与占列

| 槽位 id | 标题文字键 | 出现位置 |
|---|---|---|
| singlePlayer | menu.singlePlayerGame | 主页 |
| multiplayer | menu.multiplayer | 主页 |
| resources | menu.home.resources | 主页资源中心入口 |
| mods | menu.modsAndMaps | 主页 |
| settings | menu.settings | 主页 |
| openSourceInfo | menu.openSourceInfo | 主页 |
| resourceBrowser | browser.resourceBrowser | 资源中心；显式声明/提供图片后也在主页显示 |
| esports | browser.esportsSite | 同上 |
| extensions | menu.extension | 同上；另外还有不可隐藏的固定管理按钮 |

旧七个 id 继续有效，新版不再使用论坛/赛事的半格配对。自定义主页网格中，singlePlayer/multiplayer 的默认 span 是整行，其他卡片默认一列；想让两张主卡并排，分别显式 `span = 1`。

| `[menu.buttons.<id>]` 字段 | 默认值 | 行为 |
|---|---|---|
| order | 0 | 越小越靠前；相同值保持内置顺序 |
| span | 0 | 0沿用内置占列；1–4为指定占列，限制到实际列数 |
| hidden | false | 移除卡片并重新排布；不隐藏固定管理按钮 |
| widthPercent | 100 | 1–100，先分配槽位，再在其中居中缩窄；至少保留48dp点击宽度 |
| showBorder | 继承全局 | 单卡覆盖全局描边开关 |

全局宽度与单卡宽度不是同一概念。两列520dp宽、间距10dp时，一列255dp；单卡80%是204dp。若该卡 span=2，80%才是整个520dp的80%，即416dp。

资源中心对 resourceBrowser/esports/extensions 采用相同槽位配置。相关排序/隐藏/span，或显式全局结构字段，会将该页切为响应式网格；纯图片/宽度/描边/圆角保留大论坛卡加侧边小卡。资源中心网格使用自己的内容区计算百分比，不受主页880dp上限控制；align/offsetY不提供该页的任意坐标控制。

## 6. 图片资产：构图比像素堆砌更重要

| 资产 | 识别规则 | 建议 |
|---|---|---|
| 背景 | 根目录 background.png / background.jpg，PNG优先 | 1920×1080或2560×1440；中心裁切，边缘装饰，中心留给菜单 |
| 标题 | 根目录 title.png | 容器固定约5:1，Fit；建议1600×320透明PNG |
| 缩略图 | 根目录 icon.png | 256×256或512×512，缩小后仍易识别 |
| 卡片 | buttons/合法槽位.png / .jpg / .jpeg | 固定Crop；按两列、整行和竖屏构图分别检查 |

卡片图覆盖在原生底色之上，标题、图标与点击行为始终保留。主页成功加载的卡片图不叠额外渐变；资源中心图片成功加载后会叠一层约18%的表面遮罩。showBorder=false只去掉原生描边，不会擦掉图片里画好的边框。

主卡通常含左图标、中左标题与说明、右箭头。自定义主页网格始终使用紧凑卡片，普通工具卡不显示说明，即使桌面视口很宽；两张主卡仍显示说明。默认六卡排布中的工具说明则受响应式紧凑模式控制。为原生内容留出安静区，不要把唯一装饰放在容易被Crop裁掉的角落。图片内文字不参与本地化，建议不要烘焙原生按钮标题。

背景图受用户背景图片状态控制，启用时包内背景优先于用户手选背景。当前设置页通过「取消背景图片」关闭，再通过「恢复主题背景」或选择图片重新启用，没有名为“启用背景图片”的独立开关。背景透明度不是关闭主页所有遮罩的总开关。主页始终叠分层遮罩，不能靠background的alpha完全取消它们。

## 7. 配色：格式与直接映射

色值只支持 `#RRGGBB` / `#AARRGGBB`，8位是ARGB，不是CSS中的RGBA。支持20个角色：primary、onPrimary、primaryContainer、onPrimaryContainer、secondary、onSecondary、secondaryContainer、onSecondaryContainer、tertiary、onTertiary、tertiaryContainer、onTertiaryContainer、background、onBackground、surface、onSurface、surfaceContainer、error、onError、inversePrimary。

通用Material组件按主题配色生成颜色。新版主页与资源中心只覆盖明确提供且有效的角色，未填写的角色保留新版页面默认外观；不是每个角色都控制每个页面。

| 角色 | 新版页面中的直接用途 |
|---|---|
| primary | 主页强调色、账号边线、角标；资源中心强调色 |
| primaryContainer | 单人卡强调底色、资源中心默认大论坛卡渐变一端；该页切网格后论坛为普通资源卡 |
| secondary / secondaryContainer | 多人卡强调色，container优先；赛事图标使用secondary |
| tertiary | 资源中心扩展卡强调色 |
| surface | 普通卡底色、渐变端色与资源中心图片遮罩基色 |
| onSurface | 一般标题、页头文字；主页次要文字降低透明度 |
| onPrimaryContainer / onSecondaryContainer | 单人/多人卡文字，缺省回落onSurface或内置色 |
| surfaceContainer | 普通主页卡和资源中心默认描边；两张主卡默认用各自强调色，单卡显式showBorder=true时才优先取本角色；关闭描边时不绘制 |
| background | 主页遮罩基色与资源中心底色；主页会重设分层透明度 |
| onPrimary | 资源中心“进入论坛”胶囊的文字与箭头 |

浅色主题应同时配置底色和文字色。不要只改onSurface，让深色文字落在深色默认卡片上。部分图标与装饰仍由原生界面绘制，不能逐个移除。

## 9. 字体、音乐与游戏美术

```toml
[fonts]
regular = "fonts/regular.ttf"
bold = "fonts/bold.ttf"
```

字体路径相对于包根；bold可选。确认中文字符覆盖与再分发许可，并随包保留许可说明。没有字体配置时沿用客户端字体。部分装饰标题有自己的字体族，不应预期所有字都被替换。

音乐放包根music.<扩展名>。Android支持mp3/ogg/m4a/aac/wav/flac，桌面支持wav/ogg而不支持mp3。双端优先OGG。音量大于0、启用主题且未在对局中时播放，进对局停止，返回后恢复。改后缀不会转换编码。

游戏美术放game/，从原版assets内部的相对路径开始，例如game/units/...与game/tilesets/bitmaps/...。目录与文件名以真实游戏资源为准；不要加game/assets/。主题最后叠加在原版基线与.rwres之上。贴图切换需要等待专用重载完成，地块通常下次进图读取。连接或开局期间会阻止切换。

地图TMX、内嵌base64图像与.rwmod包内部图片不能按此机制替换。单位贴图建议保持原尺寸与透明边距，炮塔挂点、碰撞框和阴影不会自动随图片缩放。

## 10. 从设计到可以交付的示例

先写一句清楚的视觉方向，再选择背景、标题、卡片、配色、字体和文字的共同语言。只把绿色换成紫色不能展示模块的完整能力。

完整示例应交付：一个可直接导入的.rwtheme、可编辑资产/构建源码、来源与许可说明、真实页面预览。不要用程序截图伪造已经实现的控件样式，也不要为某一个示例修改客户端生产代码。

仓库中的完整参考示例为 [远洋图志 2.1 · Pelagic Atlas](../examples/themes/pelagic-atlas/README.md)：保留浅象牙纸海图、几何罗盘字标、九张票券卡片、玩家状态票据和名片印章，共39张原创图片。2.1 移除战斗室全部布局/排序/尺寸/显隐配置，PC 与 Android 各自使用内置界面，主题只改变外观。源码、资产和构建脚本均位于 `examples/themes/pelagic-atlas/`；可导入的 `pelagic-atlas.rwtheme`、同内容中文文件名 `远洋图志.rwtheme` 和 SHA-256 输出到 `build/artifacts/theme-showcase/`。同目录的 `Pelagic-Atlas-Example-Kit.zip` 是文档、源码和预览套件，应解压后取出 `.rwtheme` 导入。

推荐流程：

1. 制作独立的背景、透明标题、图标与各槽位卡片图；布局先留足原生内容安全区。
2. 用真实安装器导入最终ZIP，而不只是把文件复制到一个看起来相同的目录。
3. 在真实UIProvider.MainMenu与ResourceCenterView上加载主题，背景按正式客户端的Crop方式绘制，再叠原生页面。
4. 至少检查1280×720、640×360、400×800三个逻辑视口及资源中心，检查文字、命中区、滚动与裁切。
5. 点击单人/多人/资源入口与固定管理按钮，确认主题能停用并恢复内置外观。
6. 交付最终ZIP的SHA-256，注明预览是桌面Compose模拟视口还是真机截图。

通过逻辑视口测试不等于Android设备验证。开发与截图使用临时主题根目录和独立配置，不覆盖玩家真实themes/、resource_generated/与配置TOML。

## 11. 刷新、重新导入与排错

导入会解压成themes/<id>/。修改原始ZIP或源码目录不会改变已安装副本。更新包的完整流程是：停用 → 等待资源重载 → 删除旧包 → 重新打包导入 → 启用。

本地开发可以停用后编辑已安装目录，再刷新列表并启用。只刷新不会替换当前激活主题，只停用再启用不保证重读磁盘配置。不要修改安装目录内的id。图片同一路径可能被缓存，最终仍应重新导入、冷启动验证。

| 现象 | 优先核对 |
|---|---|
| 找不到配置 | ZIP根目录、UTF-8、theme.toml是否实际带.txt后缀 |
| 参数无效 | 表名、字段大小写、客户端版本；未知字段可能静默忽略 |
| 主卡没有并排 | 自定义网格默认主卡占整行；显式span=1；再检查手机实际列数 |
| 背景没显示 | 是否曾取消背景，能否点击“恢复主题背景”、固定文件名、图片解码 |
| 宽度改了却没变 | 880dp上限、已安装副本、全局与单卡百分比是否混淆 |
