# 等待战斗室美术包开发

战斗室是进入游戏前显示玩家、地图、房间设置和聊天的等待界面。美术包使用 ZIP 根目录的 `theme.toml`，后缀为 `.rwtheme`。主页制作见[主题包开发文档 v3](主题包开发文档v3.md)。

**战斗室美术包只修改外观，不能修改 UI 结构。** 当前界面沿用提交 `64cc613b` 的布局：按现有窗口尺寸规则选择紧凑或宽屏视图。紧凑视图保留玩家、地图/操作和下方聊天，窄屏时上下叠放；宽屏视图保留上方左侧地图/设置、右侧玩家和下方操作/聊天。`[room]` 配置不调整输入框、滚动区域、玩家列宽、按钮位置与高度规则。外观渲染集中在 `RoomThemeStyle.kt`，不会读取主题中的布局尺寸。

旧包仍可导入。原来的 `room.layout`、`room.compact`、`room.wide` 和其他结构字段会被忽略，导入时显示迁移提示；其中的背景、配色等外观继续生效。重新启用或加载已安装的旧包也遵循同一规则，无需重新制作图片。

## 可以修改的内容

| 部位 | 支持的外观 |
|---|---|
| 页面背景 | 图片、Crop/Fit/拉伸、透明度、遮罩颜色与透明度 |
| 玩家、地图、聊天、详情、操作面板 | 背景图、底色、内容色、描边、圆角、背景透明度 |
| 玩家槽位 | 通用、自己、房主、AI、准备/未准备、空位及指定出生位置的背景图；底色、描边、圆角、透明度 |
| 玩家名字 | 字体文件、字重、文字颜色、是否沿用队伍色 |
| 名片按钮 | 普通/点亮/不可用背景图、图标图、描边、圆角、配色 |
| 房间操作按钮 | 背景图、底色、文字色、描边、圆角、背景透明度 |

面板顺序和位置、列数、宽高、内外边距、玩家列顺序和显隐、字体大小和行数、按钮顺序及尺寸均由客户端决定。名片、发送等按钮不会因为配置图片而变成另一种控件；最小触控区域保持 48dp。房主权限、邀请权限、准备与同步状态、名片查询、真实地图和按钮动作仍按业务规则处理。

## 背景与面板

`[room.background]` 的 `image` 为背景图；`scale` 支持 `crop`（等比裁切，默认）、`fit`（完整显示）、`fill`（拉伸）。`alpha` 默认 100，`overlayAlpha` 默认 0，范围均为 0–100。`overlayColor` 是遮罩颜色。

面板 id 为 `players`、`map`、`chat`、`details`、`actions`，配置位于 `[room.panels.<id>]`。只装饰对应面板，不能排序、跨列、挪动或改变内边距。地图面板背景不能替换真实地图缩略图。

| 字段 | 默认值 | 范围与行为 |
|---|---|---|
| `backgroundImage` | 空 | 包内图片，按现有容器裁切，不撑大面板 |
| `backgroundColor` / `contentColor` / `borderColor` | 空 | `#RRGGBB` / `#AARRGGBB`；省略或非法值继承内置配色 |
| `borderWidth` | 1 | 0–6dp；0 取消描边，不改变内容尺寸 |
| `corner` | 8 | 0–48dp，仅改变外观 |
| `opacity` | 100 | 0–100%，只影响背景，不影响文字和点击区域 |

## 玩家槽位与名字

玩家背景图优先级：指定出生位置 → 自己 → 房主 → AI → 准备/未准备 → 通用背景。缺图继续尝试后续候选，坏图回落底色。状态图片由真实状态选择；不要在图片里画死昵称、准备标记或其他业务状态。

`slotImages` 的键为出生位置加一，字符串 `"1"`–`"1000"`，不是玩家排序后的行号。换队排序不会把图片移给另一人；负位置或观战不使用指定出生位置图。`emptyImage` 仅装饰客户端实际呈现的空位，不产生额外邀请行。

玩家的 `backgroundColor`、`borderColor`、`borderWidth`、`corner`、`opacity` 规则与面板相同，默认圆角为 6dp。玩家列固定为名称、位置、队伍、延迟、名片，主题不能隐藏、重排或调整宽度。

`nameFont` / `nameFontBold` 仅改变名字的字体家族；推荐 TTF/OTF，并确认分发许可及中文字形覆盖。缺少或加载失败时回落全局字体。`nameWeight` 范围 100–900，默认 500；客户端加粗设置仍有效。`nameUseTeamColor` 默认 true；设为 false 后可用 `nameColor` 指定统一文字色。字号、行数和字间距由客户端控制，超长姓名按内置规则截断，不扩大玩家行。

## 名片与操作按钮

名片样式位于 `[room.player.profile]`：`backgroundImage` 为普通底图，`litImage` / `unavailableImage` 随真实状态选择；`iconImage` 替换图标，`tint` 为内置图标颜色。支持 `backgroundColor`、`borderColor`、`borderWidth`、`corner`，不支持改按钮尺寸、图标尺寸或增加标签。未确认名片、未登录、AI 等情况继续遵守客户端可用性规则。

操作按钮样式位于 `[room.buttons.<id>]`，id 为：`start`、`options`、`selectMap`、`addAI`、`changeSite`、`invite`、`publish`、`lockRoom`、`memberInvites`、`sendChat`。支持 `backgroundImage`、`backgroundColor`、`contentColor`、`borderColor`、`borderWidth`、`corner`、`opacity`，范围与面板相同。按钮顺序、显示位置、尺寸和字号不能定制。`sendChat` 始终是输入框内的发送入口；输入后发送清空、Enter 发送、添加 AI 长按等行为由客户端保留。

## 旧配置迁移

移除以下字段即可消除导入迁移提示，其他外观配置可继续使用：

| 旧位置 | 忽略的字段 |
|---|---|
| `room.layout` / `room.compact` / `room.wide` | 整张表，包含列数、间距、宽度、断点和各区域高度 |
| `room.panels.<id>` | `order`、`span`、`padding` |
| `room.player` | `rowHeight`、`spacing`、`padding`、`nameSize`、`nameMaxLines`、`nameLetterSpacing`、`columnOrder`、`nameWidth`、`spawnWidth`、`teamWidth`、`pingWidth`、`showHeader`、`showPing`、`showSpawn`、`showTeam` |
| `room.player.profile` | `width`、`height`、`iconSize`、`showLabel`、`labelSize` |
| `room.buttons.<id>` | `order`、`minHeight`、`textSize` |

即使旧字段恰好等于默认值，也属于已停用配置。客户端解析和渲染都进行限制，旧包重新加载后不能恢复结构控制。本章只收紧等待室的 `[room]`；主页 `[menu]` 的现有配置另见主页规范。

迁移时保留现有图片、颜色、字体家族、字重和边框配置，删除上表字段后重新打包。用当前客户端导入时应不再出现“已忽略旧版结构字段”提示。若之前已安装相同 id 的包，先退出房间、停用并等待资源刷新结束，删除旧包后再导入；替换下载文件不会改变已安装副本。

`borderWidth = 0` 仅关闭客户端绘制的描边，图片里已经画好的线条仍属于图片。字号、行数、列宽或按钮尺寸没有替代配置，不应把旧布局参数改名后继续写入。

## 资源和交付验证

资源路径须为包内相对路径，禁止 URL、绝对路径、盘符、反斜杠、`..`、空路径段、`.` 和控制字符。危险路径拒绝导入；缺失或损坏图片和字体回落内置内容。未知面板/按钮、非法色值和缩放值给出提示并忽略或回落。背景推荐 2560×1440，槽位图用可裁切横图并保留中心安全区。

制作后分别在 PC 和 Android 验证：普通与满员房间、长昵称、准备/同步状态、名片、聊天发送、选图和开始操作。换主题前后，页面结构和可见操作应一致。还需检查高密度小横屏、竖屏、放大字体、缺图和停用主题。

完整外观示例见[远洋图志 2.1](../examples/themes/pelagic-atlas/README.md)，同目录的 `theme.toml` 和 `room-theme.example.toml` 只包含受支持的等待室外观字段。前者配合 `tools/build.py` 构建完整包；后者供单独创建最小示例时参考，不要覆盖完整包配置。`RoomThemeSpecTest` 验证旧结构字段失效和外观保留，`RoomArtThemeUiTest` 使用真实生产界面验证三个窗口尺寸分支的布局稳定、图片渲染与回落、热切换/停用、草稿焦点和真实动作，并生成预览；测试默认运行，不依赖外部已安装包。桌面 Compose 渲染的逻辑视口不能代替 Android 真机软键盘和联网开局验收。
