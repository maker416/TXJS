# 等待战斗室美术包开发

战斗室是进入游戏前显示玩家、地图、房间设置和聊天的等待界面。美术包使用 ZIP 根目录的 `theme.toml`，后缀为 `.rwtheme`。主页制作见[主题包开发文档 v3](主题包开发文档v3.md)。

**战斗室美术包支持外观装饰、默认显示的玩家头像格和可选静态信息行。** 内置外观与旧包都会显示头像；`[room.player.card] enabled = true` 只开启静态附加信息行，头像设置独立生效。扩展限制在每个玩家槽位内部。房间整体沿用提交 `64cc613b` 的布局：按现有窗口尺寸规则选择紧凑或宽屏视图。紧凑视图保留玩家、地图/操作和下方聊天，窄屏时上下叠放；宽屏视图保留上方左侧地图/设置、右侧玩家和下方操作/聊天。主题不能移动面板、输入框、滚动区域或操作按钮；真实玩家列仍由客户端管理。

旧包仍可导入。原来的 `room.layout`、`room.compact`、`room.wide` 和其他结构字段会被忽略，导入时显示迁移提示；其中的背景、配色等外观继续生效。重新启用或加载已安装的旧包也遵循同一规则，无需重新制作图片。

## 可以修改的内容

| 部位 | 支持的外观 |
|---|---|
| 页面背景 | 图片、Crop/Fit/拉伸、透明度、遮罩颜色与透明度 |
| 玩家、地图、聊天、详情、操作面板 | 背景图、底色、内容色、描边、圆角、背景透明度 |
| 玩家槽位 | 通用、自己、房主、AI、准备/未准备、空位及指定出生位置的背景图；底色、描边、圆角、透明度 |
| 玩家名字 | 字体文件、字重、文字颜色、是否沿用队伍色 |
| 玩家头像与附加信息 | 默认显示的头像格外观与默认头像；可选最多三行静态信息，每行最多四格；可按本机、房主、AI、观战或出生位置指定默认内容，已识别账号头像优先 |
| 名片按钮 | 普通/点亮/不可用背景图、图标图、描边、圆角、配色 |
| 房间操作按钮 | 背景图、底色、文字色、描边、圆角、背景透明度 |

面板顺序和位置、列数、宽高、内外边距、玩家业务列顺序和显隐、名字字号和行数、按钮顺序及尺寸均由客户端决定。玩家卡片仅开放下文列出的头像自适应上限和附加信息内容，客户端限制其尺寸和行格数量。名片、发送等按钮不会因为配置图片而变成另一种控件；最小触控区域保持 48dp。房主权限、邀请权限、准备与同步状态、名片查询、真实地图和按钮动作仍按业务规则处理。

## 背景与面板

`[room.background]` 的 `image` 为背景图；`scale` 支持 `crop`（等比裁切，默认）、`fit`（完整显示）、`fill`（拉伸）。`alpha` 默认 100，`overlayAlpha` 默认 0，范围均为 0–100。`overlayColor` 是遮罩颜色。

面板 id 为 `players`、`map`、`chat`、`details`、`actions`，配置位于 `[room.panels.<id>]`。只装饰对应面板，不能排序、跨列、挪动或改变内边距。地图面板背景不能替换真实地图缩略图。

| 字段 | 默认值 | 范围与行为 |
|---|---|---|
| `backgroundImage` | 空 | 包内图片，按现有容器裁切，不撑大面板 |
| `backgroundColor` / `contentColor` / `borderColor` | 空 | `#RRGGBB` / `#AARRGGBB`；省略或非法值继承内置配色 |
| `borderWidth` | 1 | 0–6dp；0 取消描边，不改变内容尺寸 |
| `corner` | 8 | 0–48dp，仅改变外观 |
| `opacity` | 100 | 0–100%，只影响背景，不影响文字和点击区域 |

## 玩家槽位与名字

玩家背景图优先级：指定出生位置 → 自己 → 房主 → AI → 准备/未准备 → 通用背景。缺图继续尝试后续候选，坏图回落底色。状态图片由真实状态选择；不要在图片里画死昵称、准备标记或其他业务状态。

`slotImages` 的键为出生位置加一，字符串 `"1"`–`"1000"`，不是玩家排序后的行号。换队排序不会把图片移给另一人；负位置或观战不使用指定出生位置图。`emptyImage` 仅装饰客户端实际呈现的空位，不产生额外邀请行。

玩家的 `backgroundColor`、`borderColor`、`borderWidth`、`corner`、`opacity` 规则与面板相同，默认圆角为 6dp。玩家业务列固定为名称、位置、队伍、延迟、名片，主题不能隐藏、重排或设置列宽。这些列左侧默认显示头像格，启用 `card.enabled` 后还会在下方添加静态信息行；紧凑视图由客户端为位置和队伍列保留可读宽度。

`nameFont` / `nameFontBold` 仅改变名字的字体家族；推荐 TTF/OTF，并确认分发许可及中文字形覆盖。缺少或加载失败时回落全局字体。`nameWeight` 范围 100–900，默认 500；客户端加粗设置仍有效。`nameUseTeamColor` 默认 true；设为 false 后可用 `nameColor` 指定统一文字色。字号、行数和字间距由客户端控制，超长姓名按内置规则截断，不扩大玩家行。

## 玩家卡片：头像格与静态信息行

内置外观、旧包和未配置 `[room.player.card]` 的主题默认显示头像格。`card.enabled` 默认 false，**只控制原业务列下方的静态附加信息行**；设置为 true 后显示所选内容中的 `rows`。`card.avatar.enabled` 独立默认 true，头像框样式和各内容的 `avatarImage` 不要求开启 `card.enabled`。原来的名字、出生位置、队伍、延迟、准备指示、同步进度和名片继续使用真实状态。头像格和信息格随整行点击，不新增自定义按钮动作；连接占位行不展示头像或静态信息，但保留头像列对齐。

普通字体下，无附加信息的内置玩家槽位在紧凑视图约 52dp 高（含外边距），头像约 40dp；桌面视图约 64dp 高，头像约 48dp。放大文字时内容可撑高玩家行。启用静态信息行后，头像依据名字和静态信息等稳定内容高度增大，达到有效上限后不再增大；玩家行仍容纳其内容。`avatar.size` 是自适应上限，默认 48dp，配置范围 32–64dp，并受紧凑视图 56dp、桌面视图 64dp 的平台上限约束。它不是固定头像尺寸，也不会单独把无附加信息的玩家行撑到该高度。

同一张玩家表的表头、普通玩家和连接占位行使用统一头像列宽。图片像素尺寸不参与测量，准备状态、同步进度等临时状态不会改变头像尺寸或头像列宽，避免轮询刷新时整张表跳动。

头像形状跟随实际槽位轮廓处理：未定制的胶囊形玩家行使用圆形头像；其他槽形和已定制玩家样式使用 `avatar.corner`，其默认值仍为 8dp。例如紧凑视图的内置 6dp 圆角行仍保留默认 8dp 圆角头像。该规则按槽形判断，不按 PC / Android 区分。玩家行整体还会按自身轮廓裁切，头像及其他内容不能绘制到行外。

附加信息来自 `theme.toml` 中的**固定文案**。例如“战绩：128胜 / 23负”只是美术包演示数据；客户端不会为这些文案请求账号战绩、查询外部服务或同步给房间其他成员，也不解释变量、公式或脚本。请在包说明中标明静态演示内容。账号头像属于独立的动态数据，遵循下面的优先级。

真人玩家关联到已登录账号且设置了头像时，头像格优先显示该账号头像。美术包中的 `avatarImage` 只控制没有可用账号头像时的默认图片，不能覆盖真实账号头像。AI 不查询账号，使用主题默认头像，再回落内置机器人图标。

本机玩家可直接使用 `AccountSession` 中已登录账号的头像。其他玩家必须复用已有房间身份核验结果：服务需声明支持 `room_id_membership_verified`，且能够确认对应的房间成员身份；客户端不会凭游戏昵称猜账号或对所有同名账号取图。服务不支持成员核验、未确认身份、账号未设置头像或头像加载失败时，依次回落主题默认头像和内置真人图标。现有服务不支持核验时远端玩家会显示默认头像，不能承诺房内所有已登录玩家都能显示账号头像。

```toml
[room.player.card]
enabled = true

[room.player.card.avatar]
enabled = true
size = 48
corner = 8
backgroundColor = "#172211"
borderColor = "#89B54F"
borderWidth = 1
tint = "#A8D562"

# 通用默认内容；真人的可用账号头像优先。
# 没有可用账号头像且不提供 avatarImage 时，显示内置真人/机器人图标。
[[room.player.card.content.rows]]
cells = [
  { text = "联机玩家", backgroundColor = "#263D1B", contentColor = "#D7F4BD" },
  { text = "战绩：128胜 / 23负", contentColor = "#C8CEC1" },
]

# 房主默认内容整份替换通用内容；avatarImage 不覆盖真实账号头像。
[room.player.card.host]
avatarImage = "room/avatar-host.png"

[[room.player.card.host.rows]]
cells = [
  { text = "房主", backgroundColor = "#725000", contentColor = "#FFF0A5", borderColor = "#D5A736", borderWidth = 1 },
  { text = "战绩：128胜 / 23负", contentColor = "#C8CEC1" },
]

[[room.player.card.ai.rows]]
cells = [
  { text = "进攻专家", backgroundColor = "#50205C", contentColor = "#F0CDF7" },
  { text = "AI 难度：困难", contentColor = "#C8CEC1" },
]

# 指定出生位置，非排序后的第2行。此处文案也是写死的演示内容。
[[room.player.card.slots."2".rows]]
cells = [
  { text = "防守大师", backgroundColor = "#163C6A", contentColor = "#D8E9FF" },
  { text = "AI 难度：困难", contentColor = "#C8CEC1" },
]
```

| 配置 | 字段和行为 |
|---|---|
| `room.player.card` | `enabled` 默认 false，只控制静态附加信息行；不控制头像显示 |
| `card.avatar` | `enabled` 独立默认 true，显式 false 隐藏头像；`size` 为自适应上限，默认 48dp，配置限制为 32–64dp，另受紧凑视图 56dp、桌面视图 64dp 上限约束；`corner` 默认 8dp，范围 0–48dp；`borderWidth` 默认 1dp，范围 0–6dp；`backgroundColor`、`borderColor`、`tint` 设置配色；无需开启 `card.enabled` |
| `card.content` | 通用默认内容；`avatarImage` 为包内默认头像，真人的可用账号头像优先；没有可用账号头像时尝试此图，省略、缺失或解码失败时显示内置真人/机器人图标；`rows` 为静态附加信息行 |
| `card.local` / `host` / `ai` / `spectator` | 可选默认内容覆盖，字段与 `card.content` 相同；按真实本机玩家、房主、AI、观战状态选择，其中的 `avatarImage` 也只提供默认头像 |
| `card.slots."1"`–`"1000"` | 指定出生位置的内容覆盖；观战和无效位置不使用该表 |
| `rows` | 最多保留三行，空行忽略；仅在 `card.enabled = true` 时显示，未配置则不显示信息行 |
| `rows[].cells` | 每行最多四格，客户端按可用宽度排列；文字单行截断 |
| 信息格 | `text` 为静态文案，最多 160 个字符，控制字符会被移除；`iconImage` 为可选包内图标；`contentColor`、`backgroundColor`、`borderColor`、`borderWidth`、`corner` 控制外观 |

`card.avatar.enabled = false` 只关闭左侧头像，已开启的附加信息行仍可使用；`card.enabled = false` 只关闭静态信息行，默认头像仍显示。停用主题后恢复内置头像格和账号头像规则。信息格描边默认 0，范围 0–6dp；圆角默认 6dp，范围 0–48dp。颜色与路径遵守普通战斗室资源规则，非法颜色回落、危险路径拒绝导入。缺失或损坏的信息图标不影响文字。

主题默认内容选择优先级为：非观战的指定出生位置 → 本机玩家 `local` → 房主 `host` → AI `ai` → 观战 `spectator` → 通用 `content`。只有实际配置的覆盖才参与选择，命中后**整份替换**，不会把通用内容的默认头像或信息行合并进来。例如配置了 `host` 却没有写其 `rows`，房主不会继承通用战绩行。所有覆盖（包括 `slots`）中的 `avatarImage` 都服从“可用账号头像优先”的规则。`slots` 绑定出生位置，换位会跟随位置变化；它不绑定玩家账号，也不会验证写死的“AI 难度”或胜负数。

独立可导入示例见[绿色玩家卡片](../examples/themes/room-player-cards/README.md)。旧客户端不支持此扩展，制作者应在分发说明中注明需要包含玩家卡片功能的客户端。

## 名片与操作按钮

名片样式位于 `[room.player.profile]`：`backgroundImage` 为普通底图，`litImage` / `unavailableImage` 随真实状态选择；`iconImage` 替换图标，`tint` 为内置图标颜色。支持 `backgroundColor`、`borderColor`、`borderWidth`、`corner`，不支持改按钮尺寸、图标尺寸或增加标签。未确认名片、未登录、AI 等情况继续遵守客户端可用性规则。

操作按钮样式位于 `[room.buttons.<id>]`，id 为：`start`、`options`、`selectMap`、`addAI`、`changeSite`、`invite`、`publish`、`lockRoom`、`memberInvites`、`sendChat`。支持 `backgroundImage`、`backgroundColor`、`contentColor`、`borderColor`、`borderWidth`、`corner`、`opacity`，范围与面板相同。按钮顺序、显示位置、尺寸和字号不能定制。`sendChat` 始终是输入框内的发送入口；输入后发送清空、Enter 发送、添加 AI 长按等行为由客户端保留。

## 旧配置迁移

移除以下字段即可消除导入迁移提示，其他外观配置可继续使用：

| 旧位置 | 忽略的字段 |
|---|---|
| `room.layout` / `room.compact` / `room.wide` | 整张表，包含列数、间距、宽度、断点和各区域高度 |
| `room.panels.<id>` | `order`、`span`、`padding` |
| `room.player` | `rowHeight`、`spacing`、`padding`、`nameSize`、`nameMaxLines`、`nameLetterSpacing`、`columnOrder`、`nameWidth`、`spawnWidth`、`teamWidth`、`pingWidth`、`showHeader`、`showPing`、`showSpawn`、`showTeam` |
| `room.player.profile` | `width`、`height`、`iconSize`、`showLabel`、`labelSize` |
| `room.buttons.<id>` | `order`、`minHeight`、`textSize` |

即使旧字段恰好等于默认值，也属于已停用配置。客户端解析和渲染都进行限制，旧包重新加载后不能恢复结构控制。本章只收紧等待室的 `[room]`；主页 `[menu]` 的现有配置另见主页规范。

迁移时保留现有图片、颜色、字体家族、字重和边框配置，删除上表字段后重新打包。用当前客户端导入时应不再出现“已忽略旧版结构字段”提示。若之前已安装相同 id 的包，先退出房间、停用并等待资源刷新结束，删除旧包后再导入；替换下载文件不会改变已安装副本。

`borderWidth = 0` 仅关闭客户端绘制的描边，图片里已经画好的线条仍属于图片。旧字号、业务列行数、列宽和按钮尺寸没有替代配置。新增玩家卡片使用独立的 `[room.player.card]`，不恢复上表中的任何旧字段。

## 资源和交付验证

资源路径须为包内相对路径，禁止 URL、绝对路径、盘符、反斜杠、`..`、空路径段、`.` 和控制字符。危险路径拒绝导入；缺失或损坏图片和字体回落内置内容。未知面板/按钮、非法色值和缩放值给出提示并忽略或回落。背景推荐 2560×1440，槽位图用可裁切横图并保留中心安全区。

制作后分别在 PC 和 Android 验证：普通与满员房间、长昵称、准备/同步状态、名片、聊天发送、选图和开始操作。换主题前后，房间面板位置和可见操作应一致；开启静态信息行时还需确认新增信息不会遮住真实业务列，所有玩家仍可滚动到达。验证内置外观及旧包的默认头像、`card.enabled` 和 `avatar.enabled` 独立开关、静态内容高度与尺寸上限、全表头像列对齐，以及同步进度出现/消失时头像尺寸和列宽稳定。头像需覆盖本机已登录且有图、未登录、未设图、远端已核验、服务不支持核验、身份未知、加载失败及 AI 默认头像等情况。检查高密度小横屏、竖屏、放大字体、缺图、坏图和停用主题，停用后应恢复带头像的内置玩家行。

完整外观示例见[远洋图志 2.1](../examples/themes/pelagic-atlas/README.md)，同目录的 `theme.toml` 和 `room-theme.example.toml` 只包含受支持的等待室外观字段。前者配合 `tools/build.py` 构建完整包；后者供单独创建最小示例时参考，不要覆盖完整包配置。`RoomThemeSpecTest` 验证旧结构字段失效和外观保留，`RoomArtThemeUiTest` 使用真实生产界面验证三个窗口尺寸分支的布局稳定、图片渲染与回落、热切换/停用、草稿焦点和真实动作，并生成预览；测试默认运行，不依赖外部已安装包。桌面 Compose 渲染的逻辑视口不能代替 Android 真机软键盘和联网开局验收。
