# 网游扩展包制作与接入

网游扩展包把模组和美术包作为一个不可变版本同步。它只用于所属网游，不提供单人、沙盒或自行开房的内容模式。普通模组、普通美术包、旧 Direct/HTTP 同步和原 24 小时列表申请继续保留。

## 制作与上架

使用同级 `TS/expansion-tools/game_expansion.py`（Python 3.11+，仅标准库）：

```powershell
python game_expansion.py build --game-app-id 11111111-1111-4111-8111-111111111111 --name 示例网游 --version 1.0.0 --mod example=D:/example-mod --theme D:/example-theme.rwtheme --output D:/packages/example-1.0.0.zip
```

将示例 UUID 替换为从开放平台网游卡片复制的网游 ID。模组可选，支持目录和归档。美术包可以是 `.rwtheme` 或完整目录。工具生成成品 ZIP 及 `.publish.json`，自动计算模组文件和目录摘要、美术包发布目录及完整 ZIP 摘要。包根文件如下。

```text
version.txt
expansion.toml
mods/<mod_id>.rwmod
theme/theme.toml
theme/其他美术资源
```

`version.txt` 是 UTF-8 单行版本号；AppID、名称、模组清单及美术目录位于 `expansion.toml`。版本用于展示，完整 ZIP SHA-256 是内容身份。同一网游、同一版本不能替换为不同内容；更新时提高版本号。首版最多64个模组、整包1GiB、单模组512MiB、主题256MiB、展开总量2GiB；个性化资源仍执行原32MiB单资源等目录限制。禁止路径穿越、链接、特殊文件、重复/大小写冲突路径及未声明模组。

在网游卡片导入工具生成的 `.publish.json`，平台校验归属与不可变版本，并登记包内美术目录。`expansion_binding` 包含版本、归档 SHA-256、大小及包内美术的 ID、版本和目录摘要。网游首次上架需审核，之后导入的版本进入待发布，旧版继续生效。确认发布新版后重启区服，沿用原节点密钥并等待心跳确认已经加载当前版本。

## 启动 TServer

先使用本轮 TServer 候选（公共 SDK27不变），保存已有服务器配置及节点身份插件。扩展包启动入口先核对公开平台审批元数据，再执行准备，最后启动宿主：

```powershell
powershell -NoProfile -File ./start-with-expansion.ps1 -Archive D:/packages/example-1.0.0.zip -ServerHome D:/test-server
```

入口及工具在 `TS/expansion-tools`。Linux 使用同目录的 `start-with-expansion.sh`。平台根地址可显式覆盖；生产使用 HTTPS。

准备器将原ZIP及展开后的服务器模组存入 `cache/prepared-content/<SHA>/`，原子生成中立 `prepared.json`。通过环境变量 `TSERVER_PREPARED_CONTENT` 或配置 `content.prepared_spec` 交给宿主。宿主在引擎和插件依赖扫描前替换实际模组根与启用集合，不合并普通 `mods.enabled`；实际加载来源、目录摘要和官方 checksum 成功后才发布 ready。宿主不解释 UAS、网游 AppID 或美术包业务。

准备失败不能回落启动普通模组房间。当前进程固定使用已准备版本，替换源ZIP不热更新；更新须停服、更换包、重新准备并启动。`content.prepared_spec` 默认为空，原服务器不会自动转成扩展模式。

## 玩家加入与管理

“扩展”界面有“美术包”和“网游扩展包”两个标签。扩展包单独导入、查看版本/空间、检查更新及删除；“启用并加入”只进入对应网游，不能在离线状态启用。使用中的包及必需美术不能删除或停用，普通模组页暂时只读。

客户端以实际 Direct Socket 端点在平台查到的网游和审批绑定为准，再核对大厅捕获的版本，不能只相信 ZIP 中的 AppID。确认后沿统一加入流程预约槽位、流式下载完整ZIP、验证SHA/CRC/全部目录、独立安装并一次加载模组和美术。包位于应用内部 `expansions/<AppID>/<SHA>/`，不会进入普通模组目录或网络模组缓存。已安装同摘要时直接校验复用；下载中断在本次任务内按offset续传，取消删除临时文件。

扩展模式每次原生扫描都只启用当前包的实际绝对来源；普通、网络缓存、内置及其他扩展全部禁用。成功加载和官方 checksum 复核后，客户端才发送 `CONTENT_READY`，再兑换真实游戏连接。基础美术必需；UAS或玩家身份核验失败时，仅回退专属装饰，不改变基础包和模组集合。

退房后完整恢复进入前的模组开关、原生持久设置和主题。修改引擎前写入恢复日志；异常退出后在下次原生首次扫描前恢复，不依赖打开管理页面。触发资源/内存重启保护时不强行二次重载，保留日志并要求重启。

## 协议与兼容

Direct v4 使用 `TXJSMD4` 换行前缀，保留旧游戏协议及 checksum。v4 manifest 在v3字段后追加内容修订及单一工件；`RESERVE`绑定修订，kind13为`CONTENT_READY`。预约、续租、开局门控和真实注册仍使用同一容量账本。扩展服拒绝旧 Direct/HTTP 的逐模组下载及无整包凭据的注册，旧服务器则继续原有同步。

原版注册 query 使用 `txjsmd4_<token>`；独立恢复 query 为 `txjsmd4r_<secret>_<attemptNonce>`。恢复凭据只保存在当前客户端进程，绑定实际端点、服务器实例、房间和内容修订；v4 kind14查询只确认本轮nonce对应的真实注册，不能把旧在线连接当作本次恢复成功。恢复不申请普通新槽，不从对局服务器重新下载；需要时在尚未连接的加入阶段验证并加载已有同一缓存包，再由官方存档恢复。

整包服关闭旧 HTTP Presence 的 checksum 不一致豁免。`CONTENT_READY`是客户端流程回执，不代替原版单位校验，也不声称证明恶意修改客户端真的显示了美术。所有同步/恢复凭据均脱敏、不落盘、不进入地址历史。

本轮修复了同一方法多次 Path 注入丢失早期钩子的底层问题。生成库增加注入器产物版本标记；旧生成JAR会重建，防止首次扫描恢复和额外来源钩子在实际运行中缺失。

额外模组来源在原版扫描开始前注册，并为当前扩展设置原生保留标志，避免后续重扫将其移除或返回过期列表。退出或切换版本时清除旧来源的保留标志，由原版扫描正常回收历史记录。

## 验证

客户端校验覆盖真实ZIP、Java/Python格式互通、内容隔离、缓存篡改、版本冲突、取消交付、事务恢复、来源重扫以及宽窄屏管理/加入界面。服务器使用真实官方115、真实原版Socket验证整包/offset、缺少ready拒绝、旧协议/HTTP拒绝、错误checksum拒绝、实际入房、聊天、开局及原槽nonce恢复。PC另用真实OpenGL/完整原版单位解析检验独立来源和普通模组恢复；这些证据与UI逻辑测试分别记录，不冒充完整图形客户端端到端对局。

当前本机无连接的Android设备；Android原生注册由Robolectric实际游戏库测试，不能替代真机。生产HTTPS、真实UAS及真人多人实战需单独验收。本轮不安装客户端、不覆盖现用RUN、不迁移生产数据或自动部署。
