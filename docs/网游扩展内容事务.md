# 网游扩展内容事务

网游扩展包只用于其对应服务器。`ExpansionContentController.prepare` 校验已经安装的不可变包并读取包内主题；`activate` 必须在 `GameSessionController` 的 STARTING 阶段、旧会话清理完成后调用。下载和预约由 Direct 控制器负责，本控制器不另建网络同步或容量状态。

客户端完成整包校验后，会在包目录旁保存本次校验记录。以后加入使用同一扩展包的区服时，客户端检查文件清单、文件身份和文件系统记录的变更时间。记录匹配即可跳过读取整个 ZIP 和重新解压模组，重启客户端后也可复用。升级前安装的包会在下次加载时建立记录。文件变动、记录损坏或文件系统无法可靠提供变更信息时，客户端执行完整校验。实际加载内容的单位校验和仍需与区服一致。

## 物理来源与原生扫描

`ExpansionPackages.rootDir` 使用 `AppContext.internalStoragePath("expansions/")`，与普通模组和主题目录分开。原版只扫描普通模组根目录，因此 Desktop/Android 在原生扫描完成、单位定义解析之前调用原生 `registerMod` 方法注册当前包的绝对 `.rwmod` 路径。没有复制、链接或改写普通模组根目录。

`ContentProfiles` 在每次扫描后执行来源策略：扩展模式只允许当前包声明的完整路径，普通、网络缓存、内置和其他扩展来源全部禁用。普通模式不接管已有普通模组选择，但始终禁用扩展目录残留记录。包内模组不进入普通模组管理列表；扩展正在使用时普通模组管理只读，美术包管理也不能停用必需的主题。

## 一次加载与恢复

`GameArtOverlayManager.synchronizeContent` 暂存待加载的美术目录，重建资源覆盖层后执行一次 `ModManager.applyContentProfile`。这个调用同时选择模组来源并使图片缓存失效。Desktop 保持游戏线程和主 GL 上下文所有权；Android 保持原 UI 入口与引擎锁。只有实际模组集合与要求完全一致、没有加载错误时，才提交可见主题及使用中包状态。

会话切换前保存原模组选择及原生 `SettingsEngine.modSettings`、版本和计数。扩展期间拦截原生选择保存，不把临时内容写成玩家的永久选择。恢复也使用一次同样的受控内容加载，再恢复原持久设置。主题保存项从未改成扩展主题。

`DisconnectEvent` 清理订阅是可等待的；新 `beginSession` 不能超越旧恢复屏障。取消和迟到失败使用代次 token，不会清除后来准备的包。默认的 `beginSession` 拒绝将正在使用的扩展内容带进单人、沙盒或自行开房；对应网游加入显式允许扩展模式。

## 异常退出

原始选择在修改引擎状态前原子写入扩展根目录的恢复日志。下一次进程启动时，原生扫描前恢复设置，扫描后应用原选择，再移除日志；不依赖 Compose 页面是否已经出现。若资源加载进入 `GameStartSafety` 重启保护，不强行再执行恢复重载，日志保留给重启处理。

```powershell
.\gradlew.bat :rwpp-core-api:test --tests ContentProfileTest
.\gradlew.bat :rwpp-core:desktopTest --tests io.github.rwpp.content.ExpansionContentControllerTest
.\gradlew.bat :rwpp-desktop:test --tests '*DesktopExpansionSourcesTest'
.\gradlew.bat :rwpp-android:testDebugUnitTest --tests '*AndroidExpansionSourcesTest'
```

原生来源测试使用真实游戏库的注册方法和 `.rwmod` 元数据读取，断言来源仍在独立目录且普通模组被禁用；控制器测试覆盖一次加载、真实退出事件、恢复原设置、失败回滚和旧 token。它们不能替代 PC/Android 真机渲染及实际多人对局验收。
